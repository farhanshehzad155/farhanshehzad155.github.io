The pipeline has two halves that are deliberately kept apart, and the separation is the whole
design.

### Understanding, then removal

A CV is a layout problem before it is a text problem. The same name can appear as a heading, in
an email address, in a file name, in a footer on every page, and in a sentence about a previous
employer. A rules-only parser handles the predictable cases and misses the rest, because there
are more layouts than anyone will enumerate.

So the model reads the document and reports what it found and where. It does not edit anything.

Removal is done by deterministic code against those locations. That ordering matters more than
it might look. If the model performed the redaction, the output would be probabilistic: mostly
right, occasionally wrong in a way nobody can predict or reproduce, and impossible to audit
after the fact. With the split, every removal is a rule applied to a location, so it can be
explained, re-run, and checked.
